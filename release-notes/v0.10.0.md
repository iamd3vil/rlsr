{% raw %}v0.10.0 adds native Rust and Go builders, `--split` and `--merge` for building on parallel CI runners, and more control over GitHub releases. It also changes `checksums.txt` to the format `sha256sum` reads, which breaks anything that parses the old file.

## What's new

### Native Rust and Go builders
Builds with `type: rust` or `type: go` take a list of targets and expand into one build per target. rlsr fills in the build command, the artifact path and `meta.os`/`meta.arch`/`meta.arm`/`meta.target`, so you no longer write a build entry per platform.

```yaml
builds:
  - name: "myapp"
    type: "rust"
    archive_name: "myapp-{{ meta.tag }}-{{ meta.os }}-{{ meta.arch }}"
    rust:
      targets: ["x86_64-unknown-linux-musl", "aarch64-unknown-linux-musl", "x86_64-pc-windows-gnu"]
  - name: "mytool"
    type: "go"
    archive_name: "mytool-{{ meta.tag }}-{{ meta.os }}-{{ meta.arch }}"
    go:
      targets: ["linux/amd64", "linux/arm/7", "darwin/arm64", "windows/amd64"]
      ldflags: ["-s -w", "-X main.version={{ meta.version }}"]
```

Rust builds:
- run `cargo zigbuild` by default, or `cargo build` or `cross build` if you set `tool`;
- install missing targets with rustup;
- locate the binary from `CARGO_TARGET_DIR` and the cargo profile.

Go builds:
- set `GOOS` and `GOARCH`, plus `GOARM`, `GOAMD64`, `GOARM64` or `GO386` for targets like `linux/arm/7`;
- take `main`, `flags` and `ldflags`.

Both builders use Go's os and arch names in `meta.os` and `meta.arch`, such as `darwin`, `amd64` and `arm64`, so the same `archive_name` template works for either. See [Rust builds](https://rlsr.sarat.dev/config/config/#rust) and [Go builds](https://rlsr.sarat.dev/config/config/#go).

rlsr's own release now builds with `type: rust`. One catch showed up while switching it over. cargo-zigbuild can't link a macOS binary that uses system frameworks without the macOS SDK, so rlsr builds its macOS target with `tool: cargo build` on a macOS runner.

### `--split` and `--merge`: build on parallel runners
Each CI runner runs `rlsr --split --targets <target>`, which builds and packages that target and writes a manifest of the archives to `dist/`. A final job collects every runner's `dist/` and runs `rlsr --merge`, which checksums and publishes all the archives together. The workflow moves `dist/` between jobs and no longer repeats artifact paths from `rlsr.yml`. See [Build on parallel runners](https://rlsr.sarat.dev/github-actions/#build-on-parallel-runners).

### GitHub release options
- rlsr now publishes tags with a semver prerelease part, such as `v1.0.0-rc.1`, as GitHub prereleases. Previously they became the repository's latest release, which `/releases/latest` and installers then picked up.
- `draft: true` creates the release as a draft.
- `name` sets the release title from a template, such as `"{{ meta.project_name }} {{ meta.tag }}"`.
- If a release for the tag already exists, rlsr uploads to it instead of failing. This includes drafts, so you can write the notes in GitHub first. To rerun a publish that failed partway, set `replace_existing_assets: true` and rlsr replaces the assets it already uploaded.

## Breaking change: `checksums.txt` format
Lines are now `<checksum>  <file name>`, the format `sha256sum` writes, instead of `<file name><TAB><checksum>`. Verify downloads with:

```sh
sha256sum --check --ignore-missing checksums.txt
```

## Fixes
- If a GitHub asset upload failed, rlsr exited immediately without reporting the other uploads. rlsr now tries each upload up to 3 times and reports every failure together at the end.
- The GitHub Action no longer calls the GitHub API to resolve `latest`, which failed with HTTP 403 on rate-limited shared runners.
- For Go modules with a major version suffix such as `example.com/app/v2`, `meta.project_name` is now `app` instead of `v2`.
- `rlsr.sample.yml` parses again. Its first build had no `name`.
- The `--skip-build` help text now says it skips each build's command, prehook and posthook. Release hooks still run.

## Upgrading
- If you parse `checksums.txt`, read the checksum first and the file name second.
- GitHub Actions users can pin `iamd3vil/rlsr/.github/actions/rlsr@v0.10.0`. `--split` and `--merge` need v0.10.0 or later.
