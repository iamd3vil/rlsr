{% raw %}v0.11.0 adds snapshot and nightly builds and Linux arm64 binaries. It's a breaking release: rlsr now refuses to release a commit that isn't tagged, or a working tree with uncommitted changes, unless you pass `--snapshot`.

## Breaking change: `--snapshot` for untagged builds
Before, running rlsr on an untagged commit or a dirty tree quietly skipped publishing and used the commit hash as the version. Now it stops with an error that tells you what to do. That includes `--skip-publish` dry runs.

Pass `--snapshot` to build without a release tag. Snapshots never publish, allow uncommitted changes, and get a version from `snapshot.version_template`, which by default is `1.2.4-snapshot+abc1234` after `v1.2.3`:

```yaml
snapshot:
  version_template: "{{ meta.version|incpatch }}-snapshot+{{ meta.short_commit }}"
```

If CI runs rlsr on pull requests or untagged pushes, add `--snapshot` to those runs. With the GitHub Action, that's `args: --snapshot`.

## What's new

### Nightly builds: `--nightly`
`rlsr --nightly` builds HEAD and publishes it as one rolling prerelease under the `nightly` tag. Each run replaces the previous nightly, so download links like `releases/download/nightly/myapp-nightly-linux-x86_64.zip` don't change. HEAD doesn't need a tag, but the working tree must be clean.

- `meta.tag` is the rolling tag and `meta.version` comes from `nightly.version_template`, `1.2.4-nightly.20261015+abc1234` by default. `meta.is_nightly` is set.
- The changelog lists the commits since the latest release tag.
- A nightly is always a prerelease, so it never becomes the latest release.
- If the nightly tag already points at HEAD, rlsr exits without building, so a scheduled job doesn't republish the same commit.
- Version lookups ignore the rolling tag, so it never counts as a release. Set `nightly.tag_name` to use a different name.

GitHub and GitLab delete the previous release and its tag and create them again at HEAD. GitLab also deletes the old package files. Docker pushes images tagged `:nightly`. See [Nightly](https://rlsr.sarat.dev/config/config/#nightly) and the [scheduled workflow example](https://rlsr.sarat.dev/github-actions/#nightly-builds).

rlsr publishes its own nightly every day from `master`: [nightly release](https://github.com/iamd3vil/rlsr/releases/tag/nightly).

### Linux arm64 binaries
Releases now include `rlsr-<version>-linux-arm64.zip`, and `install.sh` and the GitHub Action use it on ARM Linux machines and runners instead of refusing to install.

## Fixes
- `--skip-publish` runs failed without a valid `GITHUB_TOKEN` when the changelog template used `github_notes`, because rlsr generated the changelog just to log it. They now print a one-line warning instead.
- Rust builds only install targets with rustup when `tool` is a `cargo` command. Wrapper tools, such as a script that builds in a container, no longer get targets installed on the host that nothing uses.
- `install.sh` resolves the latest version without the rate-limited GitHub API, and fails with a clear error instead of passing a GitHub error page to `unzip`.
- Publish logs name the provider ("GitHub", "GitLab", "Docker") instead of printing `dyn rlsr::release_provider::ReleaseProvider` for each one.

## Upgrading
- Add `--snapshot` to any run on an untagged commit or a dirty tree.
- If you already use a tag called `nightly` for something else, rlsr now ignores it when looking up versions. Set `nightly.tag_name` to a different name to stop that.
- GitHub Actions users can pin `iamd3vil/rlsr/.github/actions/rlsr@v0.11.0`.
